# Upgrade: Nuxt 4.6.2 security patch (2026-10-29)

Branch `ccr-ef1e4d51-15633w` (run name `nuxt-4-6-2`; a cloud session that could push only to its own branch, so not `chore/upgrade-nuxt-4-6-2`). A record, not a rule. Progress entry: [progress.md](../progress.md#nuxt-462-security-patch-2026-10-29).

Why: `pnpm audit` listed a moderate advisory for nuxt and @nuxt/nitro-server `>=4.2.0 <4.6.2`: server route rules (`headers`, `ssr`, `redirect`, `proxy`) were skipped for case-variant paths when routing is case-insensitive.

## What affected this app

- **C1** Route rules now match the percent-decoded, lower-cased path (`@nuxt/nitro-server` adds a `request`-hook plugin; Nitro's `getRouteRules` and better-auth's `auth: 'user'` gate read its result; the app sets no `router.options.sensitive`). Probe of the production build: on 4.6.1 `/TABLE/abc` and `/Reset-Password` were served without the token pages' `cache-control: no-store, no-transform`; on 4.6.2 they have it; every other path answers as before. Case-variant API paths are 404 on both (Nitro's handler router is case-sensitive).
- **C7** Bundling: staging `wrangler.json` identical, dry run 10209 → 10218 KiB, local `wrangler dev` smoke test passed.
- **C2, C4, C5, C6, C11, C14** (SSR params, rooted paths, types, server auto-imports, navigation, Vue fixes): no change needed; typecheck, unit (2104) and full e2e cover them.
- Not affected: C3, C8, C9, C10, C12, C13, C15.

## Lessons for the next upgrade

- Diff the package, not only the notes: `npm pack <pkg>@old <pkg>@new` into a scratch folder answered "does the fix apply to this app" (where the rules are matched, whether `getRouteRules` and the auth module see it, whether decoding can throw) in minutes; the release notes alone couldn't.
- Prove a security fix with a before/after probe of the built server (S1/S3): it showed the real gap (token pages) and that nothing else moved.
- Full local e2e has load-intermittent failures: compare with the base commit under the same load before calling one a regression (a temporary `git worktree` of the pre-bump commit did it; 4.6.1 failed the same 2 tests). Recorded under progress → How to verify.
- pnpm 12 saves exact versions with `pnpm add pkg@x.y.z`; set the range back to the repo's `^` style.
- `scripts/upgrade-verify.sh` is committed without the execute bit: run it with `bash`.
