# ISS-035: The floor is not a movable frame like Figma's

- Severity: Medium
- Type: Improvement (product change)
- Status: Needs owner decision
- Audit rows: new (Frames)
- Found: 2026-11-13 (owner)

## Owner request
In Figma a frame wraps all its elements and the user can drag and move it. In Studio the floor is the wall outline, with the objects inside it. Make the floor a frame like Figma does, so the user can select it, drag it and move it with everything inside.

## Expected (Figma)
- A frame has a name label on top, a background and a boundary.
- Click the label or the frame edge to select it. Drag to move it with all children.
- Children belong to the frame. Resize changes the frame size and can clip or move children.

## Actual (Studio)
The floor shows as the wall outline. It is not a selectable object with a label and a move gesture. Pieces are placed in plan coordinates of the floor.

## Questions for the owner (do not guess)
1. Move frame: should it move the walls, the pieces and the tables together (all positions shift)? Moving the floor changes stored coordinates, so it needs a version check and one atomic batch write (AGENTS.md write rules).
2. Does the frame equal the wall outline, or is it a separate rectangle that holds the outline?
3. Can several frames be on the same page at the same time (see ISS-036)?
4. Do table QR codes, orders or 3D view depend on floor coordinates (a move must not break them)?

## Fix direction (after the decision)
Add a frame object around the floor with a label, select and move (drag, arrow keys, X and Y fields). Moving applies one offset to the outline, walls, openings and placed pieces in one guarded write. Add tests: move keeps relative positions, stale version returns 409, tenant isolation.

## How to verify
Select the frame, drag it: everything inside moves together and the layout saves and reloads with the same relative positions.
