# ISS-006: Ctrl/Cmd+0 does nothing in Studio

- Severity: Low
- Type: Gap
- Status: Needs test (Figma side unverified)
- Check ID: ZP (zoom keys)
- Test log: T26 (owner, by hand)

## Start state
Studio 2D (design view), canvas focused, any zoom other than 100 %.

## Steps to reproduce
1. Press Ctrl+0 (Cmd+0 on Mac).
2. Press Shift+0 for comparison.

## Expected (Figma)
Not verified. Figma's documented key for "Zoom to 100 %" is Shift+0. Whether Ctrl/Cmd+0 also does something in Figma must be checked by hand: the test tool cannot send Ctrl+0 (the extension refuses the key), so I could not confirm it.

## Actual (Studio)
Owner tested by hand: Ctrl+0 does not work. Shift+0 works. Shift+1, Shift+2, Ctrl/Cmd +/- all work.

## Evidence
| File | Shows |
|---|---|
| evidence/ISS-006/ (to add) | Studio before and after Ctrl+0, and Figma after Ctrl+0 |

## Suspected cause
`app/features/branches/components/DesignShopEditor.vue`, `onStudioKey`. In the `command` branch only `d`, `a`, `=`, `+` and `-` are handled; `0` falls through to `return`. Zoom to 100 % is bound to Shift+0 only (`event.code === 'Digit0'` with shiftKey). The shortcut list in `studio.ts` also lists Shift+0 only. The key is not prevented, so the browser's own page zoom reset may fire instead.

## Fix direction
First verify what Figma does with Ctrl/Cmd+0. If it zooms to 100 %: add `if (key === '0') return run(() => plan?.zoomTo(100))` in the command branch, add the key to `STUDIO_SHORTCUTS` and the zoom menu in `StudioToolbar.vue` / `DesignShopEditor.vue`, and add a unit or e2e test. If Figma does nothing, set status Won't fix and keep Shift+0.

## How to verify the fix
Press Ctrl/Cmd+0 on a zoomed plan: zoom becomes 100 % and the browser page zoom does not change.
