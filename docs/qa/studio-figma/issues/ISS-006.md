# ISS-006: Ctrl/Cmd+0 does nothing in Studio

- Severity: Medium
- Type: Gap
- Status: Fixed, needs retest (branch `claude/bold-hypatia-sx8nkl`, 2026-11-13)
- Check ID: ZP (zoom keys)
- Test log: T23 (owner, by hand)

## Start state
Studio 2D (design view), canvas focused, any zoom other than 100 %.

## Steps to reproduce
1. Press Ctrl+0 (Cmd+0 on Mac).
2. Press Shift+0 for comparison.

## Expected (Figma)
Figma's zoom menu lists "Zoom to 100%" with Ctrl+0 (seen in the menu, test T08). Shift+0 also gives 100% in Figma (T04). The key press itself was not run: the test tool cannot send Ctrl+0.

## Actual (Studio)
Owner tested by hand: Ctrl+0 does not work. Shift+0 works. Shift+1, Shift+2, Ctrl/Cmd +/- all work.

## Evidence
| File | Shows |
|---|---|
| evidence/ISS-006/ (to add) | Studio before and after Ctrl+0, and Figma after Ctrl+0 |

## Suspected cause
`app/features/branches/components/DesignShopEditor.vue`, `onStudioKey`. In the `command` branch only `d`, `a`, `=`, `+` and `-` are handled; `0` falls through to `return`. Zoom to 100 % is bound to Shift+0 only (`event.code === 'Digit0'` with shiftKey). The shortcut list in `studio.ts` also lists Shift+0 only. The key is not prevented, so the browser's own page zoom reset may fire instead.

## Fix direction
Add `if (key === '0') return run(() => plan?.zoomTo(100))` in the command branch of `onStudioKey` (`run` calls `preventDefault`, so the browser page zoom does not change). Keep Shift+0. Add Ctrl/Cmd+0 to `STUDIO_SHORTCUTS` and to the zoom menu items in `StudioToolbar.vue` and `DesignShopEditor.vue`. Add a test.

## How to verify the fix
Press Ctrl/Cmd+0 on a zoomed plan: zoom becomes 100 % and the browser page zoom does not change.

## Work (branch `claude/bold-hypatia-sx8nkl`, 2026-11-13)
Ctrl/⌘+0 zooms to 100 % and prevents the browser's page zoom; Shift+0 stays; menus and the shortcut list show it. e2e.
