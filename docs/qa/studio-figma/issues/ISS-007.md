# ISS-007: Tab and Shift+Tab do not select the next or previous item in Studio

- Severity: Low
- Type: Gap
- Status: Fixed, needs retest (branch `claude/bold-hypatia-sx8nkl`, 2026-11-13)
- Check ID: SE6
- Test log: T35, T36

## Start state
Studio 2D, Ground floor, nothing selected, canvas just clicked. Figma: Page 2 scratch page, nothing selected.

## Steps to reproduce
1. Press Escape so nothing is selected.
2. Press Tab.

## Expected (Figma)
Tab selects the next object (here Rectangle 1 became selected). Shift+Tab goes to the previous one. Not verified: Enter (select children) and Shift+Enter (select parent).

## Actual (Studio)
Nothing is selected. The browser focus moves to the floor dropdown at the top left ("Ground" shows a focus ring). This is the normal web Tab behavior.

## Evidence
| File | Shows |
|---|---|
| evidence/ISS-007/figma-01-tab-selects-next.jpg | Figma after Tab: Rectangle 1 selected |
| evidence/ISS-007/studio-01-tab-moves-browser-focus.jpg | Studio after Tab: focus ring on the floor dropdown, panel still shows the floor |

## Suspected cause
Not a bug. `onStudioKey` in `DesignShopEditor.vue` has no Tab case, so the browser handles it.

## Fix direction
Owner decision (2026-11-13): follow Figma. While the canvas has focus, Tab selects the next item and Shift+Tab the previous one, in a fixed order (suggest the Floors list order). Esc, or clicking outside the canvas, gives focus back to the page. Tab must keep working normally in the side panels and fields. Check Enter (select children) and Shift+Enter (select parent) in Figma before copying them. Add the keys to `STUDIO_SHORTCUTS`.

## How to verify the fix
With the canvas focused, Tab walks through all items in a fixed order, Shift+Tab goes back, Esc then Tab moves browser focus again. Tab inside a form field still moves between fields. Add a test for the order.

## Work (branch `claude/bold-hypatia-sx8nkl`, 2026-11-13)
While the plan has the focus, Tab / Shift+Tab select the next / previous table, piece or inside wall in the Floors list's order (`cycleSelection`, unit tested). Escape with nothing selected gives the focus back to the page, so Tab can leave (no keyboard trap). Enter/Shift+Enter not copied (not verified in Figma). e2e.
