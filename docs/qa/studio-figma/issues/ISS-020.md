# ISS-020: Inspector number fields: Shift+arrow, math, and label scrubbing missing

- Severity: Medium
- Type: Gap
- Status: Open (deferred) (branch `claude/bold-hypatia-sx8nkl`, 2026-11-13)
- Audit rows: IN2, IN3, IN4
- Found: 2026-11-13 (T78 to T84)

## Start state
Studio, select the Menu board (X 975, Y 225). Figma: a scratch rectangle.

## Steps
1. Click the X field, press Arrow Up, then Shift + Arrow Up.
2. Type `900+25` and press Enter.
3. Drag sideways on the "X (cm)" label.

## Expected (Figma, verified in Figma on 2026-11-13)
- Arrow Up adds 1; Shift + Arrow Up adds 10 (50, 51, 61).
- `10+5` becomes 15.
- Dragging the label scrubs the number live.

## Actual (Studio)
- Arrow Up adds 1. Shift + Arrow Up also adds only 1 (975, 976, 977).
- `900+25` is not calculated: the field showed 10,000 (the maximum) and the piece moved to X 10,000, which raised a "Check placement" warning.
- Dragging the label does nothing.

## Evidence
Test log T78 to T84.

## Suspected cause
Not read in detail. `DesignShopEditor.vue` uses `UInputNumber` for X, Y, rotation, width, depth and height (lines about 1613 to 1975). The Nuxt UI number input only gives plain step on the arrow keys, has no Shift step, no expression parsing and no label scrub.

## Fix direction
Check what `UInputNumber` (reka NumberField) offers in the installed version before writing code. If missing, add a small shared wrapper for the editor fields: Shift step of 10 (or the field's big step), simple math parse (`+ - * /`, numbers only, no eval) on commit, and a pointer-drag scrub on the label with undo as one step. Do not add a dependency for this. Keep min/max limits and out-of-range clamping with a clear message (not a silent jump to the maximum).

## How to verify
Unit tests for the parse function (valid, invalid, divide by zero, limits). By hand: Shift + arrow steps by 10, math commits the calculated value, label drag scrubs and is one undo step.

## Open questions
- Big step size per field (cm fields: 10 or 25?). Owner decision.

## Work (branch `claude/bold-hypatia-sx8nkl`, 2026-11-13)
Not built in this PR: it means replacing 21 number fields in 6 components with a shared field (the installed NumberField blocks `*` and `/` and has no Shift step), and the Shift step size is an owner decision. Next step after that answer.
