# ISS-014: Alt + drag to leave a copy does not work well

- Severity: Medium
- Type: Bug
- Status: Needs details
- Check ID: TR6
- Test log: T52, T53

## Start state
Studio 2D, clean page, a piece or table on the plan.

## Steps to reproduce
1. Hold Alt, press on a piece and drag it.
2. Release.

## Expected (Figma)
Alt + drag leaves the original in place and drags a copy. The copy appears as soon as the drag starts. (From the Audit's general-knowledge expectation; not re-verified here.)

## Actual (Studio)
Owner by hand: "not working well". The exact symptom was not described yet: ask the owner what happened (no copy, wrong place, the original moved, a message, a freeze?). My tool cannot send Alt during a drag, so I could not reproduce it.

## Suspected cause (from the code, not confirmed)
- `FloorPlanCanvas.vue` about line 841: the copy is decided at pointer up, from `event.altKey` at that moment, not when the drag starts. Pressing or releasing Alt during the drag changes the result.
- During the drag the original moves with the pointer (no ghost left behind), so nothing shows that a copy will be made.
- A table cannot be copied (each has its own QR code). A table's Alt + drag asks which table the copy is (`DesignShopEditor.vue` about line 962), which may feel like a failure.
- On Windows, Alt alone can focus the browser menu bar and take the keyboard from the page.

## Fix direction
Needs the owner's description first. Likely changes: decide copy from Alt at press (and let Alt toggle during the drag, like Figma), leave the original visible while the copy is dragged, and for tables show the "which table" step clearly. Add tests for pointer down with Alt, move, release.

## How to verify the fix
Alt + drag a piece: the original stays, the copy lands where released, one undo removes the copy. Alt + drag a table: the user is asked which table it is, and cancelling leaves the plan unchanged.
