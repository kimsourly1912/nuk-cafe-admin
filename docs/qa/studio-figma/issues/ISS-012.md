# ISS-012: Esc during a drag does not cancel it

- Severity: Medium
- Type: Gap
- Status: Open
- Check ID: TR7
- Test log: T44

## Start state
Studio 2D, Ground floor, clean page, a table (P02) on the plan.

## Steps to reproduce
1. Press on table P02 and drag it away.
2. Without releasing the mouse, press Esc.
3. Release the mouse.

## Expected (Figma)
Esc during a drag puts the object back where it started and nothing is changed. Not re-verified in this test; this is the Audit's expectation from general knowledge.

## Actual (Studio)
Owner tested by hand: Esc does nothing to the drag. The piece stays where it was dragged.

| File | Shows |

## Suspected cause
`FloorPlanCanvas.vue`, `keydown`: Escape only cancels placement, drawing, wall drawing, the picked corner and then the selection (doc comment above the function). It never looks at the active `gesture`. `onPointerUp` always commits a moved gesture.

## Fix direction
In `keydown`, when `gesture` is a drag (single piece, group, wall, wall end, side, resize or rotate), Escape clears the gesture and all live previews (`preview`, `groupDelta`, `liveWalls`, `liveShape`), emits nothing, and ignores the next pointer up. It must run before the "then the selection" step, so Esc does not also deselect. Add tests: press, move, Escape, release leaves the original position and emits no move; one undo step is not created.

## How to verify the fix
By hand: drag a table, press Esc before releasing: it jumps back and the undo list is unchanged. Do the same for a wall, a wall end and a group.
