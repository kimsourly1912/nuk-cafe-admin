# ISS-017: Shape and Room drawing: Shift and Alt do not work like Figma

- Severity: Medium
- Type: Gap
- Status: Open (owner decided: follow Figma, D278)
- Audit rows: DR1
- Found: 2026-11-13 (owner by hand, T63)

## Start state
Studio, any floor, Select tool.

## Steps
1. Press `S`. Hold Shift and drag a rectangle with uneven width and height.
2. While still dragging, release Shift. Then press Shift again, without moving the mouse.
3. Hold Alt while dragging.
4. Press `S` then `O` (round) and drag with uneven width and height.
5. Press `R` (Room) and drag with Alt.

## Expected (Figma)
- Hold Shift: width and height are locked equal (square). Release Shift in the same drag: the shape is free again. Both change at once, while the mouse is held.
- Hold Alt: the shape grows from the start point as its center. Shift + Alt: a square from the center.
- The ellipse tool (`O`) is free by default; Shift makes a circle.

## Actual (Studio)
Owner: not like Figma (Shift lock and release do not follow the key live). From the code:
- Shift is read only inside the pointer-move handler. Pressing or releasing Shift without moving the pointer does nothing until the next move.
- Alt is not supported by Shape. In Room, Alt means "cut the room out", which is Studio's own meaning, not Figma's "from center".
- A round shape is always equal-sided; there is no free ellipse.

## Evidence
Test log T59, T63. (Add a GIF when the fix is retested.)

## Suspected cause
`app/features/branches/components/FloorPlanCanvas.vue`, pointer move, `gesture.type === 'room'` (about line 687-698): `if (props.mode === 'shape' && (props.roundShape || event.shiftKey))` forces equal sides; `cut: props.mode === 'room' && event.altKey`. No `keydown`/`keyup` handler re-runs the preview, and the final result in `onPointerUp` (about line 853-856) uses `room.bounds` from the last preview.

## Fix direction
- Move the room/shape preview math into a pure function `drawBounds({ start, end, keepRatio, fromCenter, step })` with unit tests.
- Track the held keys (Shift, Alt) from `keydown`/`keyup` on window during the gesture and recompute the preview, so pressing or releasing a key updates at once. On release of the pointer, use the preview as shown.
- Shift keeps equal sides only while held. Alt draws from the center.
- Round shapes: free ellipse by default, Shift makes a circle (like Figma).
- Room Alt currently cuts: decide a different key for "cut" (open question below).
- Keep grid snap (25 cm, Ctrl/Cmd 5 cm).

## How to verify
Unit tests for the pure function. By hand: Shift lock/release mid-drag changes the preview with no mouse move; Alt draws from the center; Shift + Alt both; `O` is free, Shift makes a circle.

## Open questions
- What key should "cut" use in Room if Alt becomes "from center"? (Owner decision.)
- Should the default 25 cm snap stay while drawing, or become free like Figma? (See ISS-013.)
