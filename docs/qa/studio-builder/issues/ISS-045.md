# ISS-045: A new floor always starts as a copy of the floor below

- Severity: Medium
- Type: Gap
- Status: Needs owner decision (2026-11-14)
- Check ID: none
- Found: 2026-11-14, owner by hand + Claude (code review), `main` at `06bf118`

## Start state
Studio, a layout with one floor.

## Steps to reproduce
1. Floors panel → Add floor.

## Expected (reference: The Sims, Floorplanner, Revit)
A new floor can start empty, so the owner draws it freely. Copying the floor below is an option, not the only way.

## Actual
- Owner (2026-11-14): "when create a new floor it come with a preset floor instead of empty for user to draw".
- From code: `newFloor()` copies the top floor's outline with every side a wall. It has to: `floorSchema` needs an outline of at least 3 corners and 1 m², so an empty floor cannot be saved.

## Evidence
| File | Shows |
|---|---|
| (to add) studio-01-new-floor.png | A new floor right after Add floor |

## Suspected cause
- `app/features/branches/designer/starters.ts`, `newFloor()` (line 123).
- `shared/contracts/shop-layout.ts`, `floorSchema`: `outline` `minLength(3)` and the area check (line 330).
This is a model choice (floor = one outline whose sides are walls), not a slip.

## Fix direction
Solved by contract v2 in the [plan](../../../plans/studio-builder.md) (Phase 1): a floor holds 0..n slabs and a separate wall list, so it can be empty. Then: new floor empty, floor below shown faintly as a guide (`showBelow`), plus a "Copy walls from floor below" button; a "Blank" starter for the first floor. Things that read the outline must handle an empty floor: `streetDoor()`, roof and 3D cutaway, floor frame bounds (ISS-035), placement warnings, `rooms.ts`.

## How to verify the fix
Add floor → empty floor, the floor below visible as a guide; "Copy walls from floor below" copies them in one undo step; an empty floor saves and reloads; 3D shows no roof for it.

## Open questions
How should a new floor start: empty with the floor below as a guide (recommended), or empty with the walls copied?
