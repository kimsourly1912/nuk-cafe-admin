# ISS-042: Copy, duplicate and paste keep the same door and window ids

- Severity: Low
- Type: Bug
- Status: Fixed, needs retest (2026-11-14, branch `ccr-e78bff39-u70ma7`)
- Check ID: none (code review)
- Found: 2026-11-14, Claude (code review + unit probe), `main` at `06bf118`, no browser

## Start state
Studio, a floor with an inside wall that has a door.

## Steps to reproduce
1. Select the inside wall.
2. Duplicate it (Ctrl/Cmd + D), or copy and paste it.

Unit reproduction (for `designer-group.test.ts`):

```ts
duplicateSelected(layout, 'f1', [{ kind: 'wall', id: 'w' }], { x: 0, y: 50 })
layout.floors[0].walls.map(w => w.openings[0].id) // ['o1', 'o1']
```

## Expected
The copy gets new ids for its doors and windows, like it gets a new wall id.

## Actual
Both walls hold an opening with id `o1`. The contract checks that item and wall ids are unique, but not opening ids, so it saves. No visible effect today; it breaks any future feature that finds a door by id (for example a street door on an inside wall, or selecting a door).

## Suspected cause
`app/features/branches/designer/group.ts`: `duplicateSelected()` (line 80) and `pasteClipboard()` (line 133) give the wall a new id with `newLayoutId('wall')` but `structuredClone` its openings unchanged. `shared/contracts/shop-layout.ts` line 426 checks only items and walls. Confirmed by the probe.

## Fix direction
Give each copied opening a new id with its kind's prefix, as the panels do (`newLayoutId('door')`, `newLayoutId('window')`). Add a contract check "Door and window ids repeat" across all edges and walls of the layout; confirm saved staging data has no repeats first. Unit tests for duplicate and paste.

## How to verify the fix
Unit tests pass. On staging, duplicate a wall with a door; both doors can be edited separately.
