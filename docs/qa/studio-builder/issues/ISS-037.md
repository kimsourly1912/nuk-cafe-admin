# ISS-037: Removing a corner can make the layout impossible to save

- Severity: High
- Type: Bug
- Status: Fixed, needs retest (2026-11-14, branch `ccr-e78bff39-u70ma7`)
- Check ID: none (code review)
- Found: 2026-11-14, Claude (code review + unit probe), `main` at `06bf118`, no browser

## Start state
Studio, any branch, Design view. A floor whose outline has at least 4 corners. Side A (from corner i−1 to corner i) is `open` or a `railing`. Side B (from corner i to corner i+1) is a wall with a door (side A open) or a window (side A railing).

## Steps to reproduce
1. Choose Edit points on the floor.
2. Click corner i (the corner between side A and side B).
3. Press Delete.

Unit reproduction (what the probe ran; turn it into a test in `designer-outline.test.ts`):

```ts
const outline = [{ x: 0, y: 0 }, { x: 500, y: 0 }, { x: 500, y: 500 }, { x: 0, y: 500 }]
const edges = [
  { kind: 'open', openings: [] },
  { kind: 'wall', openings: [{ id: 'd1', kind: 'door', offset: 100, width: 90 }] },
  { kind: 'wall', openings: [] },
  { kind: 'wall', openings: [] },
]
const shape = removeCorner({ outline, edges }, 1)
v.safeParse(floorSchema, { id: 'f1', name: 'G', height: 300, hasRoof: true, walls: [], items: [], ...shape }) // fails
```

## Expected
The joined side has one kind, and only openings that kind can take. The layout stays valid and autosave keeps working.

## Actual
The joined side keeps side A's kind and side B's openings:
- open + door → `{"kind":"open","openings":[{"id":"d1","kind":"door","offset":600,"width":90}]}` → "An open edge has no doors or windows".
- railing + window → `{"kind":"railing","openings":[{"id":"w1","kind":"window",…}]}` → "A window needs a wall".

`useLayoutEditor.send()` validates with `layoutSchema` before saving, so autosave stops and shows the problem. Every change after that stays unsaved until the user finds and fixes this side.

Not tested in a browser: how the problem message reads on screen.

## Suspected cause
`app/features/branches/designer/outline.ts`, `removeCorner()` (lines 106–124): `merged.kind` is `shape.edges[before].kind`, but `merged.openings` joins both sides' openings. `fitEdges()` → `fitOpenings()` only checks length and overlap, not whether the kind takes the opening (`edgeTakes()` exists in the same file). Confirmed by the probe.

## Fix direction
In `removeCorner()`, filter the merged openings with `edgeTakes(merged.kind, opening.kind)` (an `open` side takes none). Optionally tell the user which doors or windows were removed. Unit tests: open + door, railing + window, railing + door (door kept), wall + wall (all kept).

## How to verify the fix
1. Unit tests above pass; removing the filter makes them fail.
2. On staging: build the start state, delete the corner. The save status goes back to Saved within a few seconds; the joined side has no door (open) or keeps only doors (railing). Capture `studio-01-after-delete.png`.
