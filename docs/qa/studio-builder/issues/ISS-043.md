# ISS-043: The editor lets a floor go over its limits, then autosave stops

- Severity: Medium
- Type: Bug
- Status: Fixed, needs retest (2026-11-14, branch `ccr-e78bff39-u70ma7`)
- Check ID: none (code review)
- Found: 2026-11-14, Claude (code review), `main` at `06bf118`, no browser

## Start state
Studio, a floor with about 150 pieces of furniture (limit 200 per floor) or about 90 inside walls (limit 100).

## Steps to reproduce
1. Select 60 pieces.
2. Duplicate (Ctrl/Cmd + D) or copy and paste them on the same floor.

## Expected
The editor refuses a change that would go over a limit, before it happens, and says why ("This floor holds at most 200 pieces"). The 64 KB per floor limit is handled the same way.

## Actual (from code; not tested in a browser)
No app code reads `LAYOUT_MAX_ITEMS_PER_FLOOR`, `LAYOUT_MAX_WALLS_PER_FLOOR` or `LAYOUT_MAX_FLOOR_BYTES`. The duplicate or paste goes through; then `useLayoutEditor.send()` fails `layoutSchema` validation, shows a problem and autosave stops until pieces are removed.

## Suspected cause (unverified)
- `app/features/branches/components/DesignShopEditor.vue`: `pasteCopied()` (line 1042), `duplicateSelection()` (line 1355), `duplicateGroup()`, adding a piece from Assets, Draw wall: none check the limits.
- `shared/contracts/shop-layout.ts` lines 21–35: the limits exist only in the contract.

## Fix direction
A pure helper, for example `floorRoom(floor, { items, walls })`, that says whether adding n items or walls (and their bytes) fits. Use it in every path that adds to a floor; refuse with a toast naming the limit. Unit tests at the edge (199 + 1 fits, 200 + 1 refused; bytes near 64 KB).

## How to verify the fix
On staging: duplicate past 200 pieces → refused with a message, nothing added, save status stays Saved.

## Work (written by the fixer)
2026-11-14, Claude Code, branch `ccr-e78bff39-u70ma7`. `floorLimitProblem(before, after)` (`designer/limits.ts`) refuses a change that takes a floor past 200 pieces, 100 inside walls or 64 KB. Only growth is refused, so a full floor can still be edited. It is checked in `useLayoutDraft.change()` for every change, so every way of adding is covered (paste, duplicate, Assets, Shape, Draw wall and future ones). A refused change is not made and a toast says why ("Not changed: A floor holds at most 200 pieces of furniture."). `change()` now returns false then, and duplicate, paste and adding a piece select nothing. Tests at the edges (199 + 1 fits, 200 + 1 refused; bytes just over 64 KB), plus a draft test; removing the guard fails it.
