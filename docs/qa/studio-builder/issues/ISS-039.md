# ISS-039: A floor outline can cross itself and still saves

- Severity: Medium
- Type: Bug
- Status: Fixed, needs retest (2026-11-14, branch `ccr-e78bff39-u70ma7`)
- Check ID: none (code review)
- Found: 2026-11-14, Claude (code review + unit probe), `main` at `06bf118`, no browser

## Start state
Studio, Design view, a rectangular floor 500 × 500 cm, Edit points.

## Steps to reproduce
1. Drag corner 2 (bottom right, 500, 500) across the left side, to about (−300, 250).
2. Release.

Unit reproduction (for `designer-outline.test.ts` and a contract test):

```ts
const shape = moveCorner({ outline: square500, edges: fourWalls }, 2, { x: -300, y: 250 }, false)
// outline: (0,0) (500,0) (-300,250) (0,500) — side 1 crosses side 3
v.safeParse(floorSchema, { ...floor, ...shape }).success // true today
```

## Expected
A floor outline is a simple polygon (no side crosses another). The drag stops at the last valid position or is refused, and the server refuses a crossing outline.

## Actual
The outline crosses itself and is accepted by the editor and by `floorSchema`. The only shape check is area ≥ 1 m², and the signed area of a crossing outline can still pass. Expected effects (not tested in a browser): the 3D floor and roof are triangulated wrongly, and "inside the floor" checks for placement warnings give wrong answers.

## Suspected cause
- `shared/contracts/shop-layout.ts`, `floorSchema` (line 330): only `signedArea ≥ 10_000`. No simple-polygon check. Confirmed by the probe.
- `app/features/branches/designer/outline.ts`, `moveCorner()` (line 38) and `moveSide()`: no crossing check.

## Fix direction
1. Add a pure `isSimplePolygon(outline)` in the contract (segment intersection for non-adjacent sides, plus no repeated consecutive points) and a `floorSchema` check "The outline crosses itself".
2. In the editor, keep the last valid position during a corner or side drag (or show the drag as invalid and snap back on release).
3. `rooms.ts` already refuses holes; make sure its results pass the new check.
Unit tests: bowtie refused, concave L shape accepted, all starters accepted. Contract change: old saved layouts with a crossing outline (if any) would fail their next save, so check staging data first.

## How to verify the fix
Unit tests pass. On staging: the drag in the steps cannot produce a crossing outline; the 3D floor matches the plan. Capture images.
