# Isolated assistant preview (D161)

PR94's opt-in same-repository, private-repository CI job deploys the complete Nuxt app to a **separate** preview. It never changes staging's Worker, database, bucket, provider, billing or import flag. Terminal Wrangler credentials are unavailable in the managed workspace; CI uses the already configured staging environment deployment credentials.

- Application Worker: `nuk-cafe-assistant-preview-app`, no public workers.dev or version URL.
- Password gateway: `nuk-cafe-assistant-preview`, forwarding through the supported `APP` service binding. Every request, including assets and public menu pages, requires HTTP Basic authentication. Gateway credentials expire after 24 hours; app Better Auth still independently checks owners/tenants.
- D1: `nuk-cafe-assistant-preview`, `ca2b3f1c-8341-4370-b4f2-bd6b25c1423a`. Only this empty/synthetic database receives the existing migrations and preview owner/category seed.
- Private R2: `nuk-cafe-assistant-preview`. Managed public domain disabled, no custom domains (checked through the authenticated API, 2026-10-06).
- Candidate help: Gemma4, single structured answer; candidate extraction: Scout. Preview enablement is experimental and does **not** satisfy the activation gate.

`prepare.mjs` rewrites only ignored generated Wrangler output, masks newly generated credentials, and writes mode-0600 files under ignored `.data/assistant-preview`. `--secrets-file` deploys secrets with code. No external inference key is used. The CI job never runs for forks, another PR/branch, public repositories or main. Only the deletion-ledger cron is retained; it shares the account's Free cron allocation.

The private repository's `assistant-preview-access` artifact contains **only** temporary preview access credentials and expires after one day. It excludes the deployment token, Better Auth secret, password hash and source documents. Repository readers can use it for review. Never copy its contents into logs, commits or PR descriptions. Download privately from the CI run; use its gateway credentials first, then its synthetic cafe-owner login at `/c/nuk/admin/login`. Use synthetic menus only: the complete app failed the Workers Free CPU gate.

`check.mjs` waits at most 30 seconds for a newly created workers.dev route to stop returning 404 (observed on the first deployment), using only read-only requests. It never retries a write or metered inference. It exercises normal Better Auth sign-in, authenticated image upload/extraction/review/correction/draft/replay/discard, and the PDF supplied-page endpoint. It then runs the existing 26 help cases serially, stopping on the first failure to conserve the free allocation. The results artifact has statuses, timings, rays and quality-check metadata only. It does not contain credentials, uploaded bytes or private/model answer text. Use actual application Worker invocation CPU/outcomes from Cloudflare observability; gateway/helper CPU and wall time cannot certify the Free 10ms budget. A supplied test raster is not a physical-phone/browser-PDF test.

Further deployments/metered checks require repository variable `ASSISTANT_PREVIEW_LIVE=true` before a PR event/rerun; unset/false skips only the live preview job. Normal unit/browser/audit/lint/typecheck remain mandatory. A skipped live job is not a quality pass or activation permission. Do not repeatedly rerun all models; first check account neurons/capacity and diagnose the failing case with safe metadata. Existing preview access remains valid until its artifact's deadline.

Before activation: Free CPU must fit the authenticated app, full help quality must pass, and the owner must review a real English menu and a physical phone. Keep staging imports disabled until those gates pass. No merge is authorized by preview deployment.

Cleanup after review: discard any private sources, confirm the deletion ledger clears, delete the gateway then application Worker, then the isolated R2 bucket and D1 database using authenticated tools. Do not touch `nuk-cafe-staging*` resources. Redeploying the preview rotates its owner and gateway passwords; expiry revokes access but does not itself delete the resources. Private sources still use the normal 24-hour lifecycle and cleanup ledger.
